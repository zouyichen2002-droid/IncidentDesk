# 扩展测试与修复记录

日期：2026-09-25。入口仍为 http://localhost:8088/ 。本轮在115条教学订单上扩展问法和查询条件覆盖。

## 最终结果

- 42个不同场景最终通过：首轮40项通过35项；补充2项单指标/空值客单价测试，并对失败项及相关场景共17项复测，17项全部通过。42是多轮测试合并后的结果，不是声称最后完整重跑了42项。
- 查询服务单元测试14项通过；Go race测试与vet通过；Nginx配置校验与网页镜像构建通过。
- 额外进行真实容器地址变更测试：保留网页容器，重建后端并强制换IP，约3.06秒恢复代理连接。重建期间有短暂502，恢复不需要重启网页代理。临时占位容器已清理，原数据卷保留。

汇总：[summary.json](evidence/extended-v1/summary.json)。逐项原始结果、独立SQL与实际SQL：[acceptance.json](evidence/extended-v1/acceptance.json)。初次失败、修复过程和代理中断的记录均保留在同目录。

## 覆盖范围

- 中文口语、英文、繁体、中英混合、错别字、代码中出现日志关键词、明确要求不查数、假设数字算术题。
- 订单数、客户去重、客单价组合；按月分组；单日/跨月/无数据月份；排除地区、多个地区、会员等级交叉筛选；最低排名、聚合后筛选、销售占比。
- 连续追问更换地区、更换指标、撤销地区、纠正年份，以及切换新问题清除原有条件。
- 没有退货字段时明确说明缺失；无订单时客单价返回NULL；执行代码请求不冒称实际运行。
- 超长输入、无效时区/模式、过长或空白历史、不存在记录、无效记录ID。

业务结果与独立手写只读SQL对照，不把模型输出当标准答案；排序问题还检查返回顺序，复合指标检查对应列，清除上下文场景检查SQL没有擅自增加筛选。一般问答检查路由和回复，并人工阅读代表性回答；不代表任意问法均正确。

## 已修复的问题

| 问题 | 原表现 | 修复及核验 |
|---|---|---|
| 客单价与客户数同时查询 | 把去重客户数误当作客单价分母，拒绝正确SQL | 只验证对应客单价表达式；实际返回订单数115、去重客户数20、客单价2427.47 |
| 追问换指标丢月份 | 问2025年1月华东订单数，却按全年查成44 | 保留日期维度字段，增加明确单月约束检查；返回正确的16 |
| 追问丢失输出要求 | 要求只返回金额，却增加地区或其他指标 | 改写继承输出列/排序/精度要求，SQL仅选择所需列 |
| 新话题自行添加日期 | 全部可用订单被限制为演示日期，数值碰巧仍正确 | 明确不根据目录添加时间；复测SQL无WHERE/HAVING过滤 |
| 无效记录ID | 输入错误返回500 | 在查数据库前验证UUID，返回400；合法但不存在ID仍返回404 |
| 后端重建后网页502 | 代理缓存旧容器地址 | 本机Compose代理配置使用Docker DNS动态解析，真实换址验证自动恢复 |

单月校验覆盖常见month条件、日期等值/区间/上下界；多月范围和复杂时间表达仍需更多针对性验证，不把它当作完整SQL语义证明。Kubernetes部署仍沿用既有未同步问数的边界；本轮代理恢复修复与验收针对本机Compose。
