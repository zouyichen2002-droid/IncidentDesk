# 对话入口升级

> 历史阶段文档：2026-09-25 后续已实现持久会话，刷新清空等限制由 [CONVERSATION_MEMORY.md](CONVERSATION_MEMORY.md) 替代；下文保留此前验收记录。

日期：2026-09-25。使用同一个入口 http://localhost:8088/ ，默认选择“自动识别”。

## 本轮解决的问题

此前“你是谁”被归为范围外，所有澄清被固定提示覆盖；Go 的关键词快捷分流还会将“客单价是什么意思”“写排序代码”等一般问题误送进查询。现在自动模式先理解完整语义，再返回回答、具体追问、业务查询或日志调查。

- 支持问候、身份、能力介绍、一般知识、概念解释、翻译、写作和编程建议。
- 不明确的问题针对缺少的信息追问，补充条件后可继续查询。
- 当前页面支持最近对话上下文，例如“一季度各地区销售额”→“那华东呢”→“改成二月”。每次实际查询都保存补全后的独立问题，并重新执行和检查权限。
- 模型回答与实际查询结果分开标识。一般回答不是数据库证据；业务表格、SQL 与来源沿用已有查询链路。
- “新对话”清空当前上下文；切换应用内页面后返回会保留对话。普通对话刷新后不恢复；业务查询仍可从历史打开，打开历史业务查询可继续追问。界面最多保留最近12条消息，发送最近8条，单条最多2000字。
- 非空输入支持1–2000字；空白、超长或不合法请求给出输入错误。联网、电脑文件、执行代码等未接入能力会说明限制并提供帮助，不声称已完成。

## 实现与参考

继续保留 [didilili/shopkeeper-agent](https://github.com/didilili/shopkeeper-agent) 的字段/指标/值域混合检索、LangGraph 多节点编排、SQL 校验纠错和执行。其 README 声明基于尚硅谷“掌柜问数”，属于社区整理实现。此次新增的普通问答、语义分流、对话上下文、权限目录和回复幂等属于本项目扩展，不冒称上游原有能力。

Go 仍负责身份和当前数据权限；模型只能建议路由，不能授予权限。能力介绍收到的是当前账号可见的目录。历史消息只允许 user/assistant，客户端历史属于不可信上下文；不把它作为权限或数据库结果凭据。

模型输出简化为 `kind + content`，Python 转为统一接口响应。无上下文的独立查询保留用户原话，避免路由改写年份或指标；仅追问需要补全。Go 在 `unified_requests.decision` 保存首次决定；同一请求重试复用回答或补全的问题，并发首次决定一致。迁移 `005_conversation.sql` 可重复执行，已加入本机部署和测试脚本。SQL 查询仍是持久任务；一般回复是同步请求。

接口：`POST /api/v1/queries` 新增可选 `history:[{role,content}]`。HTTP 200 的 `status=answer` 使用 `answer`，`status=clarification` 使用 `clarification`；HTTP 202 继续返回任务类型和ID，业务查询还返回补全后的 `question`。明确手动选择“业务数据”/“日志与证据”仍强制使用对应工具；连续追问请用默认自动模式。

## 验证

执行命令：

```sh
./scripts/test-go.sh
(cd query && uv run python -m unittest discover -s tests -v)
(cd web && npm run build)
uv run --project worker python scripts/conversation_acceptance.py
ACCEPTANCE_OUT=docs/evidence/conversation-v1/regression uv run --project worker python scripts/merged_acceptance.py
```

本轮最终结果：新增对话验收30/30；原回归24项通过并针对性复测2项强制业务模式的权限检查，共26项通过；Python查询测试12/12、Go race/vet、前端构建均通过。证据在 `docs/evidence/conversation-v1/`，汇总见 `summary.json`，保留初次失败与修正过程。测试包括短输入、身份和能力、指标解释、一般排障、编程、翻译、写作、实时信息限制、具体追问、三轮查数、话题切换、权限与幂等，以及原业务查询/调查回归。数值用已有 SQL 基线及独立 SQL 结果核对：华东一季度 107373，华东二月 17508。路由测试按有限样例与关键词断言验证，并人工查看回答；不代表任意问法100%正确。

首轮发现模型在条件充分时过度追问，以及将回复填进错误字段，已针对性修正。首轮证据保留为 `before-repair.json`。空白问号可收到使用帮助或追问；权限回归分别验证强制工具入口与自动模式的完整业务问题。数值比较按 Decimal 比较，避免把 JSON 的 `107373.0` 与 `107373` 误判成不同数值。照片问题给出了具体的本地查找帮助并追问操作系统，验收允许直接帮助或合理追问；删除/缺少利润字段允许具体解释，不要求一种固定措辞。

## 当前边界

仍是115条教学订单、一个业务数据集。本次没有增加数据源、联网搜索或生产部署，没有实现跨刷新/跨设备的持久聊天会话，也没有让模型直接解读历史表格作为已验证的新结论。具体业务数值需重新查询。混合业务与日志请求会询问先处理哪一项。完整通用助手能力还需要更多真实错例验证。
