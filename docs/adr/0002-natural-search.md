# ADR 0002：自然语言检索、全量索引与历史关联

日期：2026-09-24；状态：本地实现并验收。补充 ADR 0001，不改变 Go 权限/审批边界。

用户要求完成大数据检索和历史关联，并使用 Mistral 实现“一句话找到证据”。

- Go 对自然语言请求先验身份，仅把当前可访问的服务目录交给 Python。Mistral Chat Completions 使用严格 JSON Schema 输出服务、时区内起止时间、模式和至多 6 个关键词。Go 再验证范围（最多 7 天）、查询形状和实时成员关系，才创建持久任务。相同用户/幂等键/原始请求只对应一个任务。模型不生成 SQL，也不提供授权。
- SQLite 保留原始日志，增加服务/时间/ID、服务/级别/时间索引和 message 字段 FTS5。新增、更新、删除由触发器维护全文索引；首次索引构建在事务内进行。SQL 参数绑定，关键词按 FTS 字面短语 OR 查询。
- 默认异常模式按级别分层；候选异常不超过 10,000 条时提取低频归一化消息模式。代表记录与游标分页结合，默认每页 20 条、最多 3 页。报告保留全量条件统计、证据数量和抽样说明。严重级别不等同于数据集人工异常标签。
- SQLite 查询在线程池运行，SQL 设置进度截止时间。首次大库建索引需要维护窗口；本机 1592 万行一次性构建约 118 秒。不把单机 SQLite 称为分布式生产日志平台。
- 部署按服务和时间查询，包含窗口前最后一次有效部署作为基线；Git 仅读取这些部署关联的 SHA；运行手册读取截止时间之前的历史版本。公开日志缺少对应 Git/发布/手册时明确缺失，不使用本地订单演示材料。
- Mistral 只接收脱敏、受限证据子集，优先保留关联的非日志证据，并以 UTF-8 字节保守估计限制输入预算。自然语言计划和调查回答分别记录实际模型/Token/耗时。模型输入统一使用已校验的服务 ID，避免把来源别名误判为跨服务资料。回答和候选的证据 ID 在输出 Schema 中枚举，且引用必须指向本次提供的证据；Go 保存时再次检查引用。引用有效不代表结论已经由人工判定正确。模型错误否认已命中的日志时，由统计一致性保护替换成原始证据，并明确标记原因。
- API key 仅由忽略的本机 `.env` 或 Kubernetes 已存在 Secret 注入 context/worker。Web、demo 不接收模型密钥。模型出错不冒充模型成功。

取舍：没有配置密钥时仅提供明确标记的规则解析；已配置 Mistral 不静默回退。查询是受控关键词检索与异常代表抽样，不宣称任意语义问题或所有低频事件都能召回；没有实现向量索引或任意文件/互联网搜索。

接口依据：[Mistral Chat Completion](https://docs.mistral.ai/studio/conversations/chat-completion)、[Structured Output](https://docs.mistral.ai/studio/conversations/structured-output/custom)。运行证据见 [SEARCH_V2.md](../SEARCH_V2.md)。
